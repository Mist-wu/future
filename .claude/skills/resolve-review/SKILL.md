# 结算和复盘

命令都在工作区根目录运行。

## 结算

Polymarket 的题自动结算：

```bash
python3 scripts/polymarket.py check
```

输出里标着“待人工”的题，是平台关闭了但结果不明确。打开链接看平台的说明，再和用户商量按哪种结果记。

手动题由你提建议，用户确认：

1. 读题目文件里的判定标准。
2. 搜证据，优先用判定标准里指定的来源。
3. 把结论和证据链接发给用户：按标准应判 yes、no，还是证据不足。
4. 用户确认后记账：

   ```bash
   python3 scripts/ledger.py resolve q0001 yes --note "一句话依据" --evidence "链接"
   ```

题目本身出了问题时记 `void`，比如判定标准有歧义，或者前提不存在了。作废的题不计分。

事件在截止日前就已经发生的，可以提前结算。

## 复盘

每道题结算后，在题目文件的“复盘”一节写几行：

- 结果，以及六个数各自的值。
- 回看五步法的记录：基准率选得对不对，哪条证据权重给错了，触发条件有没有起作用。
- 归类：判断有缺陷，还是判断合理但运气不好。说明理由。

写复盘时只评价当时能得到的信息，不拿事后才知道的事来批评当时的判断。

## 教训文件

`lessons.md` 只收重复出现的错误。写完复盘后翻一遍以前的复盘：同一类缺陷在 3 道以上的题里出现，就写一条教训，注明是哪几道题，以后怎么做。

成绩单上的校准表也是教训的来源。比如某个概率段有 10 道以上的题，实际发生的比例和预测差了 15 个百分点以上，就写进去。

## 提交

```bash
git add -A && git commit -m "结算 q0001：<结果>" && git push
git -C private add -A && git -C private commit -m "结算和复盘"
```

第二条命令用于私有题。`private/` 没有改动时它会提示没有可提交的内容，不用处理。

私有题的复盘写在 `private/questions/` 里它自己的文件中。要把私有题的教训写进 `lessons.md`，只写方法上的教训，不带题目内容。
